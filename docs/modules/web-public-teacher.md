# Модуль web-public-teacher — публічний сайт і кабінет викладача

Сторінки, які бачать студенти, батьки й викладачі: пошук розкладу, розклад групи / викладача / аудиторії,
заміни, дзвінки, «Про систему», реєстрація за запрошенням і кабінет викладача. Плюс PWA для публічних сторінок.

## Сторінки

| Маршрут | Файл | Що робить |
|---|---|---|
| `/` | `pages/public/HomePage.tsx` | Великий миттєвий пошук (↑/↓, Enter, Esc; латиниця, одруківки, англ. розкладка), обране й нещодавні, «Зараз» (пара, відлік, чисельник/знаменник, тиждень), заміни дня (свої групи першими), розклад останньої переглянутої цілі на сьогодні, усі групи за курсами, дзвінки, Telegram-бот із QR |
| `/g/:code` | `pages/public/GroupSchedulePage.tsx` | Код у будь-якому написанні веде на канонічну адресу (`/g/4ki1` → `/g/4КІ1`); невідомий код — схожі групи й пошук |
| `/t/:id`, `/r/:id` | `TeacherSchedulePage.tsx`, `RoomSchedulePage.tsx` | Те саме для викладача й аудиторії; в аудиторії — зайнятість тижня (сітка день × пара, відсоток, «зараз вільна / зайнята») |
| `/changes` | `pages/public/ChangesPage.tsx` | Сьогодні / наступний день / будь-яка дата; таблиця у форматі розпорядження (Група · Пара · За розкладом · Причина · По заміні · Ауд.), на телефоні — картки; пошук групи, курси, «лише мої» (обрані групи й викладачі), номер розпорядження, PNG/PDF; оновлення щохвилини для сьогодні |
| `/bells` | `pages/public/BellsPage.tsx` | Профіль, що діє: дні з однаковими дзвінками однією колонкою, перерви, сьогоднішня колонка й поточна пара з прогресом, живий відлік; інші профілі — у розгортанні |
| `/about` | `pages/public/AboutPage.tsx` | Що вміє система, легенда станів (справжні `LessonCell`), чисельник/знаменник, клавіші, встановлення PWA, бот із QR, вхід для викладачів |
| `/invite/:token` | `pages/public/InvitePage.tsx` | Логін + пароль + повтор (zod), вимоги до пароля наживо; 409 → під полем «логін», 400 → під полями, 410 → «запрошення вже недійсне»; невідомий/прострочений/використаний токен — окремі стани |
| `/me` | `pages/teacher/MyDayPage.tsx` | Нові заміни: прохання (підтвердити / «не можу») і призначені заміни NOTIFY («Добре» / «не можу»), «не можу» з коментарем, оптимістично, нові — наживо через SSE з підсвіткою й сповіщенням), мої пари (день/тиждень), мої заміни, Telegram (одноразове посилання + QR), календар, друк |
| `/me/absences` | `pages/teacher/MyAbsencesPage.tsx` | Форма (діапазон у календарі, увесь день / окремі пари, причина, коментар) з попереднім переглядом зачеплених пар; список «попереду» (майбутні можна видалити з підтвердженням) і «минулі» |
| `/me/preferences` | `pages/teacher/MyPreferencesPage.tsx` | Сітка день × пара: порожньо → небажано → неможливо (клік, Enter, 1/2/0, стрілки), мої пари за поточним розкладом у клітинках, легенда, панель «не збережено» й попередження при переході |

Спільний каркас розкладу — `components/public/schedule/`: `SchedulePage` (заголовок, дії, друк, QR),
`ScheduleExplorer` (День/Тиждень, `DateNav`/`WeekNav`, дні тижня, підгрупи, «зараз», зміни тижня, офлайн),
`ScheduleActions` (обране, Web Share, календар, друк, QR, копіювати посилання), `schedule-params.ts` (стан в адресі),
`schedule-utils.ts` (чиста логіка). Друк — `components/public/print/`. Кабінет — `components/teacher/`.

API: `src/api/public.ts`, `src/api/me.ts`. Мок-API: `src/mocks/handlers/public.ts`, `src/mocks/handlers/me.ts`.

## Рішення

- **Стан сторінки розкладу в адресі**: `?date=&view=day|week&sub=1`. Вихідний день у посиланні → найближчий понеділок.
  Без `view` — останній явний вибір (localStorage `rozklad.scheduleView`), інакше тиждень на ≥1024 px і день на телефоні.
- **Дані тижня одним запитом** (пн–пт), день перемикається без запиту; інший тиждень того самого власника показується
  поверх попереднього (притемнено), без «блимання» силуетом.
- **Пошук на головній — локальний** за довідниками `/public/groups|teachers|rooms` тією самою нормалізацією, що й сервер
  (`lib/search`): результат на кожну літеру без запиту. Якщо довідники не завантажились — запасний шлях через `/public/search`.
- **Зміни видно публічно після «публікації» розпорядження** (DOMAIN §7: заняття змінюються під час публікації). Сторінка
  «Заміни» без `order` пише «ще не опубліковано» (сьогодні/майбутнє) або «змін не було» (минуле).
- **«Лише мої»** — з обраного (групи за id, викладачі за прізвищем та ініціалами; «Крисак Л.» ≠ «Крисак А.О.»).
- **Друк**: аркуш рендериться порталом у `<body>` і показується лише під час друку (`print.css`, іменовані сторінки
  A4 альбомно / книжково), тож Ctrl+P теж друкує тиждень. Табличка на двері — QR-код сторінки, великий код групи/аудиторії.
- **ICS**: файл вантажиться через клієнт API (працює й з мок-API), підписка — `webcal://…/api/public/ics/{group|teacher}/{id}.ics`
  і Google Календар (`calendar.google.com/calendar/render?cid=`; потрібна публічна адреса сайту). Для аудиторій ICS немає (CONTRACTS §1).
- **QR завжди на білій табличці** (`data-theme="light"`), щоб сканувався і в темній темі; SVG для завантаження — з чорними модулями.
- **Побажання зберігаються явно** («Зберегти» на липкій панелі зі лічильником змін), бо зазвичай міняють кілька клітинок;
  перехід з незбереженими змінами питає підтвердження (`useBlocker`). Стани відрізняються не лише кольором: пунктир / штрихування.
- **Відповідь на запит заміни оптимістична** (`useReplyToChange`): картка одразу переходить у «Мої заміни», при помилці
  повертається з поясненням. Нові запити — `useServerEvent('change.updated')` (зʼєднання тримає макет кабінету).
- **«Нові заміни»** (`SubstitutionRequests`): прохання CONFIRM («Підтверджую» / «Не можу», строк) і повідомлення про
  призначені заміни NOTIFY без відповіді, від сьогодні («Добре» / «Не можу», без строку; опублікована — з позначкою «у
  розпорядженні»). Стан після відповіді — як у core (`api/me.ts → answered`): «Добре» лишає статус, «Не можу» відхиляє
  ще не опубліковану заміну, а опубліковану лишає з позначкою «Ви повідомили, що не можете» в «Мої заміни».
- **PWA** (`vite.config.ts`, `public/pwa-*.png`, `apple-touch-icon.png`): `autoUpdate`, реєстрація окремим скриптом
  (`script-defer`, сумісно з CSP), заздалегідь кешується лише оболонка; частини коду — CacheFirst, публічні відповіді API
  (meta, довідники, дзвінки, розклад, заміни) — NetworkFirst з тайм-аутом 5 с, тож останні переглянуті тижні відкриваються
  офлайн. Запити розкладу мають `networkMode: 'offlineFirst'` (інакше TanStack Query без мережі навіть не спробує кеш SW).
  У dev Service Worker PWA вимкнений — там працює воркер MSW. Іконки відрендерено з геометрії `favicon.svg` (лінія маршруту).
- **Офлайн чесно позначений**: без мережі над розкладом пише, що показано збережену копію.
- **«Про проєкт»** на сторінці «Про систему» лише каже, що це курсовий проєкт, і дає посилання на офіційний сайт vtc.vn.ua —
  без імен (їх власник додасть сам, якщо треба).

  такої дисципліни, ні викладача — не вигадуємо).
- «Сьогодні» і два наступні навчальні дні — детерміновані демо-зміни без конфліктів (`DayPlanner`): заміна вільним
  колегою тієї ж дисципліни, скасування останньої пари, переїзд у вільну аудиторію, додаткова пара у вікні зміни, запити

## Відомі обмеження

- Документи розпоряджень (`/api/documents/orders/{id}.png|pdf`) у мок-API немає (область notification) — посилання PNG/PDF
  працюють лише з бекендом.
- Викладач не може дізнатися, чи Telegram уже привʼязано (`GET /api/notify/bindings` — лише ADMIN), тож кабінет завжди
  пропонує отримати посилання.
- Стан SSE-зʼєднання кабінету (`useLiveConnection`) тримає макет і не віддає сторінкам — індикатора «наживо» на `/me` немає.
- Шапка сайту (не цей модуль) на 768 px ширша за екран на ~15–21 px; сторінки модуля вміщаються.
- Lighthouse не вимірювався; PWA перевірено збіркою (маніфест, `sw.js`), встановлення на телефон — ні.
