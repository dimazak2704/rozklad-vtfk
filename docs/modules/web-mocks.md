# Модуль web-mocks — мок-API SPA (MSW)

Мета: агенти сторінок і розробник працюють з інтерфейсом без бекенду, Keycloak і Docker, на даних із
реального розкладу коледжу. Код — `web/src/mocks/`, інструкція для розробника — `web/src/mocks/README.md`.

## Відповідальність

- Інфраструктура MSW 2: Service Worker у браузері (`npm run dev:mock`, e2e) і `msw/node` у Vitest.
- Збирання обробників з `src/mocks/handlers/*.ts` (одна область — один файл, експорт `handlers`).
- Спільні інструменти: ProblemDetail як у бекенді, затримка і симуляція збоїв, сховища стану, потік SSE,
  детерміновані UUID.
- Базовий набір даних (`src/mocks/fixtures/`): 56 груп, 107 викладачів, 128 дисциплін, 45 аудиторій,
  1077 занять шаблону з `seed/schedule-2025-26.xlsx`, календар I семестру 2026/2027, генератор ScheduleDto.
- Ендпоінти: `GET /api/public/meta`, `GET /api/public/search`, `GET /api/events/stream`. Решту додають
  агенти сторінок у своїх `handlers/<область>.ts`.

## Рішення

- **Моки лише в dev.** `main.tsx` запускає MSW до першого рендеру, якщо `import.meta.env.DEV && VITE_USE_MOCKS === '1'`;
  у production-збірці умова стає `false` і код MSW з даними вирізається (перевірено: у `dist` немає ні MSW,
  ні прізвищ із фікстур). Плагін `rozklad:drop-mock-service-worker` у `vite.config.ts` прибирає
  `mockServiceWorker.js` з `dist`, тож у nginx-образ і майбутній кеш PWA він не потрапляє.
  Збій запуску MSW не ховається: замість застосунку — повідомлення, бо інакше запити мовчки пішли б на справжній API.
- **Режим `mock` Vite** (`npm run dev:mock` = `vite --mode mock`) читає `web/.env.mock` без секретів, тому файл
  у git (виняток у `web/.gitignore`, корінь ховає всі `.env.*`).
- **Фіктивний користувач — той самий механізм `VITE_DEV_AUTH_ROLES`.** У мок-режимі ролі можна змінити у
  вкладці через `sessionStorage['rozklad.mockRoles']` (`''` — гість); з реальним бекендом сховище не читається
  (`src/auth/roles.ts → devRoles`). Макети адмінки й кабінету в мок-режимі відкривають SSE і для фіктивного
  користувача (`MOCK_API` у `src/api/client.ts`): потік подій дає мок.
- **E2E завжди з моками і гостем.** `playwright.config.ts` стартує власний `vite` з `VITE_USE_MOCKS=1`,
  `VITE_DEV_AUTH_ROLES=''` (змінні процесу важливіші за локальні `.env*`) на `PW_PORT`; `reuseExistingServer: false`,
  бо чужий dev-сервер на тому ж порту (без моків або з ролями) дав би хибні результати. Ролі в тесті —
  `loginWithMockRoles(page, 'ADMIN')` з `web/e2e/support/mock-auth.ts`.
- **Незмоковані запити:** у браузері — `bypass` (йдуть на проксі як є), у Vitest — `error`, щоб тест не ходив
  у мережу тихо.
- **Затримка і збої — одна прослойка** `controlHandler` перед обробниками областей (лише в браузері):
  `real` затримка (100–400 мс) або `VITE_MOCK_DELAY`/`?mockDelay=`; `?mockError=<400–599|network>` і
  `&mockErrorPath=` в адресі сторінки чи запиту. Хибне значення прапорця — помилка, а не тиша.
- **Стан областей — у сховищах** `createMockStore`/`createMockCollection`, які скидаються після кожного тесту
  (`src/test/setup.ts`) і через `window.__rozkladMocks.reset()`. У браузері стан живе до перезавантаження.
- **Помилки як у core:** `type` `urn:rozklad:problem:<slug>` (slug-и з `ProblemTypes`), українські `title`/`detail`,
  `requestId` у тілі й заголовку `X-Request-Id`, `errors[]` за полем, `conflicts[]`, `code` для 422.
  Обробник може кинути таку відповідь (`throw notFound(...)`) — MSW підтримує це офіційно; правило ESLint
  `only-throw-error` для `src/mocks` дозволяє кидати `Response`.
- **Дані — без вигадок.** Таблицю розбирає `web/scripts/mocks/extract_timetable.py` за правилами DOMAIN §10–11
  (обʼєднані клітинки, чисельник/знаменник, підгрупи «/» і «(п)», прізвище в клітинці дисципліни); виправлено
  одруківки DOMAIN §10 і ще дві очевидні («Вернигорв», «Шидлорвська»). Повні назви — лише відомих абревіатур і
  спеціальності КІ; решта — абревіатура з `needsReview: true`. Місткість, корпус, циклова комісія, розмір групи,
  ім'я викладача — `null`; `lessonKind` — `MIXED` (у таблиці не вказано). Ініціали куратора підтягуються до
  прізвища в заняттях, якщо однофамільців немає; «Харченко» без ініціалів розвʼязується за дисципліною.
- **Генератор розкладу** матеріалізує шаблон за DOMAIN §6: парність (19.10.2026 — 8 тиждень, знаменник),
  практика групи прибирає її пари, дистанційний режим ставить `online`, дні поза семестром — `studyDay: false`.
  Зміни накладаються через `overlay(date, lessons)` на всі заняття дати, тож заміну видно групі й обом викладачам.
  id занять детерміновані (`mockId`), тож посилання й кеш стабільні між перезавантаженнями.
- **Потоки:** один викладач, та сама дисципліна й аудиторія в кількох груп одночасно — спільний `streamId`.
- **Залежності для сторінок:** `@tanstack/react-virtual` (віртуалізація великих сіток), `vite-plugin-pwa@2`
  (підтримує Vite 8; ще не підключений у `vite.config.ts` — це робота агента публічних сторінок).

## Як перевірити

```bash
cd web
npm run dev:mock                         # http://localhost:5180, адмінка й кабінет без Keycloak
npx vitest run src/mocks src/auth        # фікстури, генератор, meta/search, kit, сховища, SSE, ролі
PW_PORT=5180 npx playwright test         # e2e з моками: оболонка + e2e/mocks.spec.ts
python -I web/scripts/mocks/extract_timetable.py seed/schedule-2025-26.xlsx web/src/mocks/fixtures/timetable.data.ts  # з кореня
```

## Відомі обмеження

- Змоковано лише meta, search і SSE; `/api/me`, розклади, заміни, розпорядження тощо — у агентів сторінок.
- Стан у памʼяті не переживає перезавантаження сторінки (так задумано: завжди відомий початковий стан).
- Довгий потік SSE через Service Worker перевірено в Chromium (e2e); інші браузери не перевірялися.
